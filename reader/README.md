# 划即记阅读器

不要用 ZCode 的 PDF 面板读这个流程——它只能看到"当前选区"，看完就丢。
用这个小阅读器：**鼠标拖选生词，松手即记录**，整篇读完一次性交给我。

## 怎么指定读哪一篇

`1-提取PDF.bat` 支持两种选法，**结果都会打印标题让你确认**：

| 方式 | 操作 | 适合 |
|---|---|---|
| **拖拽**（推荐） | 把 PDF 直接拖到 `1-提取PDF.bat` 图标上 | `pdf\` 里堆了很多篇时 |
| **双击 + 选编号** | 双击运行，列出 `pdf\` 里所有 PDF，输入编号 | 只有一两篇时 |

> `current.pdf` 是自动生成的"当前这篇"的副本，**不会出现在列表里**，不用担心选错它。
> 换文章时，上一轮已划的生词会自动归档，不会串到新文章上。

## 每天两步

```
① 把 PDF 丢进 ..\pdf\
② 拖到（或双击）1-提取PDF.bat  → 打印标题，确认没选错
③ 双击 2-开始阅读.bat   → 浏览器自动打开
④ 读；生词直接拖选，松手就记（右下角会闪 ✓）
⑤ 读完点右上「结束本次」
⑥ 回 ZCode 对我说：分析一下
```

## 它记了什么

每次拖选记录：**选中的词 / 段落号 / 页码 / 时间戳**。
同时自动计时，所以你不用报"第一遍用时"了——点「结束本次」时已经算好。

- **选错了**：鼠标移到右侧那条生词上，点 **×** 删掉，该段高亮同时取消。
- **关掉页面再打开**：已记录的生词和段落高亮都会恢复（存在 `state.json` 里）。
- 只有"在正文里按下鼠标"才会触发记录，页面加载时的残留选区不会被误记。

## 数据存在哪

```
%LOCALAPPDATA%\daily-reading\
├── state.json              当前这次
├── last.json               最近一次完成的结果  ← 我读这个
└── sessions\2026-11-02T...json   历史归档
```

**不放在 daily reading 文件夹里**，避免和你同步网盘的 Markdown 混在一起。
要备份就备份这个目录。

## 端口

默认 `127.0.0.1:8765`。被占用的话：

```bat
set PORT=8766 && node server.js
```

## 故障排查

| 现象 | 原因 |
|---|---|
| 页面显示"还没有 article.json" | 先跑 `1-提取PDF.bat` |
| 提取时报"没有文字层" | 扫描版 PDF，需先 OCR |
| 打开是空白 | 服务没起来，看命令行窗口有没有报错 |
| 选中没记录 | 选区超过 120 字符会被忽略（防止误选整段） |
| 浏览器没自动打开 | 手动访问 `http://127.0.0.1:8765/` |
